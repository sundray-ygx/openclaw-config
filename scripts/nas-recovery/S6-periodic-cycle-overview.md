## 一、级联总图（复盘→计划→批复落库）

```
日：  每晚 22:00 日反思 ──→ 22:30 日安排滚动修正 ──→ 次日 08:00 早报展示
周：  周五 19:30 周复盘首发 ──→ 22:10 周计划起草 ──→ 周日 21:30 周末复盘提醒 → 22:00 日反思 → 22:15 周复盘完整版更新 ──→ 22:30 周计划复核（批复落库 deadline=周日 22:30，含7天日安排）
月：  月末 22:00 月复盘 ──→ 23:30 月计划起草 ──→ 批复落库批(落库+回查+次月7天日安排+周计划向后复核)
季：  季末 22:30 季复盘 ──→ 23:00 季计划起草 ──→ 批复落库(季首前)
年：  12/31 23:00 年复盘 ──→ 23:10 年计划(单会话三连 23:10年→23:25季→23:40月) ──→ 跨年批复 → 1/1 落库
```

三条级联铁律：
- **Ⅰ 复盘→计划**：每个周期的计划起草紧跟同周期复盘之后（计划消费复盘的「下周期行动建议」）
- **Ⅱ 上级→下级**：年→季→月→周→日逐层递进，上层输出=下层直接输入
- **Ⅲ 就绪时点**：计划必须在周期开始前定好（周计划周日22:30前落库〔2026-09-14 起，原周一12:00〕、月计划次月1号前、季计划季首前）
- **级联Ⅳ 上层落库→下层复核**：月计划落库批检查已落库周计划覆盖差异→推复核卡不直改；周计划起草显式消费当月月计划

## 七、时序红线（任何调整不能破坏）

1. **复盘→计划先后**：每个计划起草必须排在其同周期复盘之后（数据依赖）
2. **就绪 deadline**：周计划周日 22:30 前落库（2026-09-14 起，原周一 12:00）；月计划次月 1 号前；季计划季首前；日安排次日 08:00 早报前
3. **间隔余量**：上游执行时长+留缓冲。已知实测：日反思约 7 分钟；月复盘读全月数据更重
4. **窗口+guard 模式**：月/季任务放 28-31 窗口、末天 guard。调整的是窗口内时刻，窗口本身（28-31/3,6,9,12）是重试兜底机制，一般不动
5. **12/31 让路分支**：月/季计划 cron 的 guard 含 12/31 静默让路，任何调整不得删除
6. **prompt 内嵌时间同步**：任务名（如「季计划起草（季末22:40）」）和 prompt 正文硬编码时间点（如「今晚 22:00 daily-reflection」）必须随 cron 调度同步修改，否则 guard 判断错位
