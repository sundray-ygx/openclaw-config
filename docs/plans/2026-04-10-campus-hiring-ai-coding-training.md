# 校招新员工AI Coding入职培训方案

## 背景与目标

**目标人群**: 校招入职新员工（软件开发工程师）
**核心目标**: 通过SDD规范驱动编程实践，让新员工掌握AI-Coding全过程，快速融入团队AI-Coding工作方式

## SDD过程框架（基于OpenSpec）

```
┌─────────────────────────────────────────────────────────────┐
│                    SDD 完整流程                              │
├─────────────────────────────────────────────────────────────┤
│  Phase 1: Proposal（需求提案）                               │
│    → 明确课题目标、范围、验收标准                             │
│    → 产出: proposal.md                                       │
├─────────────────────────────────────────────────────────────┤
│  Phase 2: Specs（需求规格）                                  │
│    → 编写Given/When/Then格式的测试用例                      │
│    → 定义功能规格、边界条件、异常场景                         │
│    → 产出: specs/*.md                                        │
├─────────────────────────────────────────────────────────────┤
│  Phase 3: Design（技术设计）                                 │
│    → 架构设计、模块划分、接口定义                             │
│    → 技术选型、依赖分析                                       │
│    → 产出: design.md                                         │
├─────────────────────────────────────────────────────────────┤
│  Phase 4: Tasks（任务拆解）                                  │
│    → 细化为可执行的原子任务                                   │
│    → 产出: tasks.md                                          │
├─────────────────────────────────────────────────────────────┤
│  Phase 5: Implementation（AI辅助实现）                       │
│    → 使用AI Coding工具（Claude/Codex等）按Task实现          │
│    → 每完成一个Task提交代码                                   │
├─────────────────────────────────────────────────────────────┤
│  Phase 6: Verification（验证）                              │
│    → 运行测试验证符合Specs                                   │
│    → Code Review、重构优化                                    │
│    → 产出: 可运行的完整项目                                   │
└─────────────────────────────────────────────────────────────┘
```

## 过程产物清单（用于检验）

新员工需提交以下产物，证明完整执行SDD流程：

| 阶段 | 产物文件 | 检验要点 |
|------|----------|----------|
| Proposal | `proposal.md` | 目标清晰、范围明确、有验收标准 |
| Specs | `specs/*.md` | 使用Given/When/Then格式，覆盖正常/异常场景 |
| Design | `design.md` | 架构合理、接口定义清晰 |
| Tasks | `tasks.md` | 任务粒度适中、可执行、有完成标记 |
| Implementation | 源代码 + 提交记录 | 按Task提交、commit message规范 |
| Verification | 测试报告 + 运行截图 | 测试通过率、代码覆盖率 |

## 执行方式

1. **课题选择**: 从待选课题中选择1个（或自选经评审通过）
2. **时间周期**: 建议3-5天完成
3. **评审方式**: 提交完整过程产物 + 代码演示
4. **评价维度**: SDD流程完整性、代码质量、AI工具使用熟练度

## 待选课题（8组+）

### 课题组1: CLI工具类

#### 课题1.1: 智能Git提交助手
**难度**: ⭐⭐
**描述**: 开发一个CLI工具，自动分析git diff内容，使用AI生成规范的commit message
**技术栈**: Python/Node.js + Git命令 + LLM API
**核心功能**:
- 读取git diff/staged changes
- 调用LLM生成符合Conventional Commits规范的message
- 支持交互式编辑确认
- 支持自定义prompt模板

#### 课题1.2: 项目脚手架生成器
**难度**: ⭐⭐⭐
**描述**: 开发一个CLI工具，根据用户输入的项目类型和技术栈，生成标准化的项目结构
**技术栈**: Node.js/Python + 模板引擎
**核心功能**:
- 交互式问卷收集项目信息
- 支持多种项目模板（Web/CLI/API/库）
- 自动生成README、LICENSE、基础配置
- 支持自定义模板扩展
