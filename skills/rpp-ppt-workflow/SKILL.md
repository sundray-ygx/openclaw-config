# RPP + PPT 战略执行工作方法论

基于深信服"从战略到执行"培训课件提炼，结合克里斯坦森RPP框架与Leavitt/Schneier PPT框架的完整方法论。

## 核心公式

> **组织能力 × 执行力 = 战略落地**

## 使用场景

1. **制定工作计划** - 从战略到执行的全流程规划
2. **诊断执行瓶颈** - 使用RPP框架分析组织能力短板
3. **系统化推进** - 使用PPT框架确保执行落地
4. **阶段复盘** - 验证商业闭环，调整战略路径

---

## 第一阶段：诊断现状（RPP框架）

RPP框架回答"为什么执行会失败"，由内而外诊断组织能力。

### 三个层次（改变难度：易 → 难）

| 层次 | 核心问题 | 诊断清单 |
|------|----------|----------|
| **资源 (Resources)** | 我们"有什么" | 人力、技术、资金、品牌、数据是否匹配？ |
| **流程 (Processes)** | 我们"怎么做" | 现有流程是否支撑目标？流程是否成为阻碍？ |
| **优先事项 (Priorities)** | 我们"为什么做" | 决策过滤器是否清晰？什么被认为是重要的？ |

### 关键洞察

- 最深层的瓶颈往往在**优先事项层**
- 前一阶段的成功流程会成为下一阶段的阻碍
- 流程越成功，越难改变

## 第二阶段：规划路径（6条核心原则）

```
选择 → 成长 → 闭环 → 定力 → 路径 → 赢取
 ①      ②      ③      ④      ⑤      ⑥
```

### 原则① 选择：聚焦关键而独特的客户价值

**核心要点：**
- **聚焦**：不能同时追求过多目标，有限资源快速形成突破
- **关键**：目标客户的代表性深层需求
- **独特**：基于市场尚未满足的需求，最大化禀赋优势
- **充满想象力**：融入产业大周期，百亿级市场空间

**RPP视角**："聚焦" = 优先事项作为决策过滤器

### 原则② 成长：积小胜为大胜的分阶段路径

**核心要点：**
- 终局目标 → 格局型目标 → 阶段里程碑 → 阶段性杠杆解
- **战略四要素**：目标客户、价值主张、竞争优势、盈利模式

**RPP警惕**：成长阶段"流程陷阱"
- 早期灵活 → 成长期标准化 → 成熟期精细化

**PPT动态校准**：每个阶段PPT三支柱需重新校准

### 原则③ 闭环：快速迭代验证商业闭环

**量化验证指标：**
- 样本量：不少于10个有代表性的目标客户
- 命中率：联合创新100%，其他客户70%+
- 销售效率：销售周期验证商业价值吸引力

**关键原则：**
- 快速成功或快速失败，不追求完美
- 端到端视角：销售 → 产品 → 交付 → 服务
- 价值兑现 > 卖给客户

**RPP深度洞察**：三个指标对应RPP三层的量化验证

### 原则④ 定力：战略方向坚定，阶段目标柔性

**定力：**
- 战略大方向 = 终局目标，共识后执行要坚决
- 聚焦"信号"，过滤"噪声"
- 孤立事件或非战略选择，敢于放弃

**柔性：**
- 开放对待战术性机会，纳入战略大方向
- 短期目标服从长期目标
- 审时度势、顺势而为

**为什么难？** 组织的流程和优先事项一旦为当前业务优化到极致，就会自动排斥任何需要不同流程/优先事项的新方向。

### 原则⑤ 路径：足够的压强 + 高杠杆策略

**压强原则：**
- 资源集中投入，承担经过计算后的风险
- 端到端推广目标、策略和资源配置方案
- 聚焦重点行业、客群、市场，打穿打透

**高杠杆策略四要素：**
1. 找准"痛点"客户，针尖策略突破
2. 突破标杆客户，形成带动效应
3. 锁定高切换成本客户，规模+范围效应
4. 围绕渠道价值驱动力设计销售策略

### 原则⑥ 赢取：极致关注客户体验

**核心公式：**
> 客户体验好 = 真正兑现价值，保留客户 > 获取客户

**关键动作：**
- 在客户最痛的价值点上创造惊喜
- 多渠道实时倾听客户声音，鼓励反馈
- 核心人员走到客户中去
- 站在客户视角代入体验自己的产品

## 第三阶段：执行落地（PPT三支柱）

PPT框架回答"如何系统化推进执行"，自外向内落地。

### 三支柱结构

```
┌─────────────────────────────────────┐
│           人 (People)               │
│  • 识别技能需求  • 提供培训支持      │
│  • 建设变革文化  • 管理团队精力      │
├─────────────────────────────────────┤
│          流程 (Process)             │
│  • 清晰定义期望  • 消除瓶颈          │
│  • 跨部门协作    • 持续反馈迭代      │
├─────────────────────────────────────┤
│         技术 (Technology)           │
│  • 基于需求选型  • 系统化部署        │
│  • 驱动数字采纳  • 持续优化投资      │
└─────────────────────────────────────┘
```

### 关键原则

**执行顺序：人 → 流程 → 技术**

1. **先确保人对齐** - 识别技能需求，提供培训支持
2. **再设计流程** - 清晰定义期望与路径，消除瓶颈
3. **最后引入技术** - 技术是最后一步，而非第一步

### 阶段演进规律

| 阶段 | 人 | 流程 | 技术 |
|------|-----|------|------|
| 早期 | 拓荒型人才 | 灵活流程 | MVP |
| 成长期 | 规模化人才 | 标准化流程 | 系统化平台 |
| 成熟期 | 精细化人才 | 精细化流程 | 智能化工具 |

## 第四阶段：决策检查清单

### 战略决策层（选择 + 定力）

- [ ] 是否明确了"做什么"与"不做什么"？
- [ ] 是否建立了决策过滤器？
- [ ] 能否识别偶发机会是否在主航道上？
- [ ] 战略大方向是否形成共识？

### 执行验证层（成长 + 闭环）

- [ ] 阶段里程碑是否清晰可衡量？
- [ ] 战略四要素是否明确？
- [ ] 是否有足够的样本量验证？
- [ ] 端到端流程是否打通？
- [ ] 价值是否真正兑现？

### 市场突破层（路径 + 赢取）

- [ ] 资源是否集中投入？
- [ ] 是否找到高杠杆策略？
- [ ] 客户体验是否极致关注？
- [ ] 是否站在客户视角验证？

### 组织底盘层（承载）

- [ ] 人/流程/技术三支柱是否对齐？
- [ ] 文化是否支撑变革？
- [ ] 架构是否连接三支柱？
- [ ] 是否需要组织架构创新？

## 关键提醒

1. **流程陷阱**：前一阶段的成功流程可能成为下一阶段的阻碍
2. **优先事项阻力**："快速失败"的真正阻力是组织优先事项的隐性排斥
3. **组织架构创新**：有时需要组织架构的创新来守护战略方向（如惠普喷墨打印机案例）
4. **PPT动态校准**：每个阶段PPT三支柱需重新校准，不能一成不变
5. **技术是最后一步**：先人对齐，再设计流程，最后引入技术

## 方法论总结

**RPP诊断能力瓶颈 + PPT指导落地执行 = 战略到执行的完整方法论**

**7条原则的内在逻辑链：**

```
选择(①) → 成长(②) → 闭环(③) → 赢取(⑥)
  ↓           ↓           ↓
RPP优先事项  RPP流程+PPT  PPT人+技术
定义做什么   阶段解码+    选对人+
不做什么     端到端验证   技术赋能

定力(④) → 路径(⑤)
  ↓           ↓
RPP优先事项  压强+高杠杆
建立决策     策略
过滤器
```

**架构连接三支柱 + 文化是操作系统**
