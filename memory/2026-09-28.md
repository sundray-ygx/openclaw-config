- **结论**: ①"网页访问无响应"经全链路诊断（DNS/证书/nginx/容器/外部网络双重探测 + 用户 IP 浏览器日志核对）确认服务端无故障，用户端 09:47-09:49 请求全部 200，判定为瞬时网络抖动，已自愈无需处理。②附带发现并修复 zai bridge IPv6 故障：nginx 静态解析 api.z.ai 优先拿 AAAA 记录，ECS 无 IPv6 出口致 `Network is unreachable`（当日已失败 12+ 次），改运行时解析 `resolver ... ipv6=off` 强制 IPv4，真实调用验证通过。
- **文件变更**:
  - `/etc/nginx/conf.d/newapi-upstream.conf` — `/zai/v1/` location：静态 `proxy_pass https://api.z.ai/...` 改为 `set $zai_target` + `resolver 100.100.2.136 100.100.2.138 ipv6=off valid=300s` + `rewrite` 拼路径（备份 `/root/nginx-backup-newapi-upstream-20260928`）
  - volc 的 location 未动（ark.volces.com 无 AAAA 记录、无故障，改了反而引入运行时 DNS 依赖）

- **教训**: nginx `proxy_pass` 写死域名 = 启动时一次性静态解析，多 A/AAAA 记录时行为不可控；对无 IPv6 出口的主机，上游域名带 AAAA 时必须用 `resolver + 变量 + ipv6=off` 模式
