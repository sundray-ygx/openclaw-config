# 2026-04-05 日志

### [PROJECT:OpenClaw] cron 重复触发问题排查

- **结论**: 不是 cron 重复触发，也不是 gateway bug。根因是**旧配置使用百炼 API 导致配额限制**，已切换至 zai/glm-5
- **详细分析**:
  1. NAS 备份 cron（02:00）每天只触发**1次**，runs 记录正常
  2. 旧配置使用 bailian provider 下的模型（kimi-k2.5、qwen3.5-plus 等），受 provider 级别配额限制
  3. failover 链路会尝试多个 bailian 模型，但都受同一配额约束
  4. zai provider 的模型不受影响，稳定性更高
  5. 已将默认模型切换为 `zai/glm-5`，相关脚本已同步修改
- **失败模式**（历史记录）:
  - 4/1, 4/3, 4/5: 失败（超时）
  - 4/2, 4/4: 成功（failover 到了 zai/glm-5）
- **实际影响**（历史）:
  - 每次失败产生 ~18-36 个 lane task error 日志（看起来像重复触发，实际是 failover 重试）
  - 备份脚本本身不受影响（实际在 exec 层成功执行），只是 LLM 汇报环节超时
- **解决方案**: 已完成系统性切换至 zai/glm-5
