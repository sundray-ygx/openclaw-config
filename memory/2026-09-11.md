### [PROJECT:OpenClaw系统] 9.3 升级后 doctor/tui ownership 故障攻坚（已解决）
- **根因三层**: ① 手工系统级 unit 无 openclaw marker，9.3 CLI "user-first" 无法识别所有权 → doctor verdict unresolved；② 尝试迁 user 级失败：9.3 install 用 `busctl --user --json=short`，systemd 239（Al8）不支持 --json（243+ 才有）→ SERVICE_DEFINITION_UNKNOWN，**user 级迁移在本机技术不可行**；③ doctor 维护需独占状态库，必须停机跑
- **最终方案**: 保留系统级部署 + `OPENCLAW_SERVICE_REPAIR_POLICY=external openclaw doctor --fix --yes`（跳过服务管理块）+ systemd-run 独立单元跑停机自愈脚本（停→doctor→无论成败拉回）
- **结果**: doctor --fix 完整跑通（cron store normalized），网关自愈拉回，三飞书通道 running，0 报错
- **意外收获**: 用户手工恢复系统 unit 时 enable 了它——修复了 8-13 迁移以来开机自启实际失效的隐患
- **遗留警告**: main/scheduler agent 缺 message 工具 allowlist（不影响实际收发）；coding agent memory search 配 openai 无 key（semantic recall 不可用）；NODE_COMPILE_CACHE 未设（性能建议）
- **教训**: ① busctl --json 需 systemd≥243，老系统上 openclaw gateway install 必失败；② 停机操作必须用 systemd-run 独立单元 + 自愈兜底（第一次迁移脚本无兜底导致 28 分钟失联）；③ exec 会话随网关死亡，跨停机任务必须脱离网关 cgroup
- **标签**: #openclaw-9.3 #doctor #systemd #busctl #incident
