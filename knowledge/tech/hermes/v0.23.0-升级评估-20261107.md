# Hermes Agent v0.23.0 升级可行性评估报告（ECS）

评估日期：2026-11-07 · 模式：决策门（只读核实完毕，未动任何配置）· 评估人：小群（ECS 会话）

---

## 〇、结论先行

**可行，推荐执行，风险等级：低-中**。核心依据：

1. **数据库零迁移**：v0.23.0 `SCHEMA_VERSION = 32`，与本机 state.db（schema=32，54M）完全一致——不存在 schema 单向锁死风险，回滚无数据库障碍。这是与上次 0.19→0.22.4 升级（schema 22→32）最大的区别，那次最怕的就是回不去。
2. **配置兼容**：`SUPPORT_FLOOR_VERSION = 12`，当前 `_config_version: 51` 远高于地板，向前兼容。
3. **切换机制现成**：复用 2026-10-29 定版的软链+unit sed 双点切换，旧目录全部保留，回滚 <5 分钟。
4. **一个结构性风险必须绕开**：npm 桥接包与 0.22.4 备位目录**同名冲突**，绝不能直接 `npm install -g hermes-agent@0.23.0`（会就地摧毁 0.22.4 退路目录），必须手动解包到版本化目录。

### 1.2 定版切换机制（2026-10-29）

- 脚本：`/root/scripts/utils/hermes-version-switch.sh`（双版本对 V19/V22 硬编码）+ `/root/scripts/quick-switch.sh` 统一入口
- 切换点：① `/usr/bin/hermes` 软链 ② systemd unit 的 venv/PATH 路径 sed ③ daemon-reload
- **铁律**：不动 `/usr/lib/node_modules/hermes-agent` 目录名——pm 按 install 路径哈希登记依赖，改名触发 repair 循环（2026-10-29 实测教训）
- 防连坐：所有切换动作经 `systemd-run` 脱离会话进程树派发

### 2.1 版本跨距

v0.22.4 → v0.23.0：跨 v0.22.5/6/7 三个补丁 + 大版本（since v0.22.0 约 10,080 commits / 1,950 PRs）。npm registry 已有 `hermes-agent@0.23.0`（第三方 npm bridge，upstream 钉死 commit `2bd378ed`）。

| 参数 | v0.23.0 | 本机现状 | 判定 |

| config 地板 | 12 | 51 | ✅ 兼容 |

### 2.3 对本机业务的影响分析

| 领域 | 变化 | 影响 |
|---|---|---|
| **Gateway/飞书** | 单 gateway 架构继续深化；v0.23.0 修复了 v0.22.0 架构引入的一批回归（slash commands、/retry、/refine、clarify cards、reasoning display）；飞书新增 clarify 卡片+选择器；平台 adapter 全部插件化（官方称"Nothing changes for users"） | 正面：0.19.0 是单 gateway 架构前的旧世界，升级即跳过 0.22.x 的过渡期问题 |

| **性能** | cron 共享 prompt cache、一次性调用省 ~1,570 prompt tokens、patch/write_file 毫秒级返回、长稳 gateway 内存释放 | 正面收益 |
| **Webapp** | 桌面工作区浏览器化，**默认关闭** | 不开启即无攻击面，无影响 |

## 三、方案设计

### 3.1 方案比选

| 方案 | 描述 | 推荐 | 理由 |
|---|---|---|---|
| **A：npm 桥接包手动解包到版本化目录**（推荐） | tarball 解包到 `hermes-agent-0.23.0` → 手动跑 `node scripts/postinstall.js`（sparse checkout + uv venv + Python 3.14）→ 扩展切换脚本三分支 → 切软链+unit | ⭐⭐⭐⭐⭐ | 与 0.22.4 备位目录形态同构（都是 npm bridge），运维心智一致；桥接包自动管 uv/Python/commit 钉扎；不动任何现有目录 |
| B：GitHub tarball 手动装（NAS 模式） | curl release tarball → 手动 uv venv → editable install | ⭐⭐⭐ | 可行但要手动管 Python 3.14 + uv + install-stamp（NAS 踩过 vunknown 坑），工作量大于 A 且形态与现役不一致 |
| C：暂缓观望 | 等 0.23.x 补丁 | ⭐⭐ | 0.23.0 发布才 2 天；但本机现役是 0.19.0（4 个月前的版本），跳过 0.22.7 直接上 0.23.0 与等补丁再上差异不大；schema 32 已冻结 |

### 3.2 方案 A 执行步骤（批准后实施）

**阶段 0：前置备份**（不动现役）
```
1. cp ~/.hermes/config.yaml ~/.hermes/config.yaml.pre-0.23.0.bak
2. state.db 一致性快照（sqlite backup API → /root/backups/）
3. cp systemd unit → unit.pre-0.23.0.bak
4. 读完整 postinstall.js（本次仅读前 60 行，确认无 npm 环境依赖后再跑）
```

**阶段 1：装到版本化目录**（不动现役，随时可弃）
```
1. curl npm tarball（43K）→ 解包到 /usr/lib/node_modules/hermes-agent-0.23.0/
2. node scripts/postinstall.js（sparse checkout 上游 v0.23.0 + uv venv + 托管 Python 3.14）
   ⚠️ 网络风险点：uv/Python 从 GitHub 拉取，raw 通道今天间歇失败——失败则重试/手动兜底
3. 补装平台 extras：uv pip install -e '.[feishu]'（技能定版惯例，防 lazy-install 首连失败）
4. 干跑验证（干净 env）：env -i HOME=/root PATH=... hermes-agent-0.23.0/.../venv/bin/python -m hermes_cli.main --version
5. 沙箱冒烟：HERMES_HOME 指向临时目录跑 config check / sessions list
   + 真实 home 布局审计（技能教训：state.db 若是软链，新版 resolve() 校验可能炸——本机 state.db 是真实文件非软链，预判无碍，仍要核）
```

**阶段 2：扩展切换脚本**（三分支路由）
```
1. hermes-version-switch.sh 加 V23 分支（含 unit PATH 的三向 sed）；quick-switch.sh 加 0.23 动作
2. 脚本改前备份 .bak；bash -n 干跑
```

**阶段 3：切换 + 验证**（gateway 重启 ~1 分钟瞬断窗口）
```
1. 选无任务窗口（当前无 hermes cron，避开 root crontab 整点任务即可）
2. quick-switch.sh 0.23（systemd-run 脱离本会话派发，防 TUI 连坐）
3. 验证六项：切换日志退出码 / systemctl is-active / readlink 软链 / hermes --version /
   journalctl FAILURE 计数 / 飞书 WebSocket connected 日志
4. Boss 飞书实测收发（黄金指标）
5. TUI 退出重开（定版规约）
```

**阶段 4：收尾**（验证稳定后，另行决策）
```
磁盘回收到 ~77%：删 0.22.4 备位目录（4.1G）——需 Boss 单独批准（见决策点 D3）
```

### 3.3 回滚方案（<5 分钟，双向现成）

```
quick-switch.sh 0.19   # 回 0.19.0（或 0.22，退路二选一）
```
- schema 32=32：无数据库回滚需求
- config.yaml 有 .pre-0.23.0.bak：需要时一键恢复
- 0.19.0/0.22.4 目录全程不动：天然回滚保险

## 四、风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| npm 桥接包同名冲突（误跑 npm i -g 摧毁 0.22.4） | — | 高 | 方案层面已绕开：只手动解包，绝不 npm i -g |
| postinstall 手动跑失败（依赖 npm 上下文） | 低 | 中 | 阶段 1 先读完整脚本确认；备选 npm prefix 局部安装法 |
| GitHub 网络抖动（uv/Python 拉取失败） | 中 | 低 | 重试 + 手动下载兜底；今天 git/npm 通道均实测可达 |
| gateway 起不来 | 低 | 高（飞书断） | 回滚 <5min + journalctl 三步诊断法（技能已固化） |
| TUI 会话被切换连坐 | 中 | 低 | systemd-run 脱离派发（定版模式）；切换后 TUI 重开 |
| 磁盘装满 | 低 | 高 | 装前 8.3G 可用 vs 预计 3-4G 需求，够；装完 ~87% 触发哨兵告警属预期，验证后删 0.22.4 回收 |
| 0.23.0 新版回归 bug（发布仅 2 天） | 中 | 中 | 回滚极快；0.23.0 本身修复了大量 0.22.x 回归 |
| ExecStartPre（load_secrets）独立故障误判为版本问题 | 低 | 中 | 诊断顺序固化：先证伪切换成功，再查 ExecStartPre |
