# OpenClaw 历史升级踩坑汇总与规避方案

> 整理日期：2026-09-11
> 目的：汇总历次升级/配置变更中的踩坑记录，制定规避方案，确保下次升级平稳

---

## 一、历史踩坑清单

### 🟥 坑 1：升级后 skillhub CLI 无法运行（Python 兼容性）

**时间**：2026-03-26
**版本**：升级至 v2026.3.23
**现象**：skillhub 命令报错，无法运行
**根因**：skillhub 依赖 Python 3.7+，但系统默认 Python 是 3.6
**影响**：技能管理功能失效
**修复**：升级 Python 版本 / 调整 skillhub 依赖
**严重程度**：🟡 中危

**规避方案**：
- 升级前检查 Python 版本：`python3 --version`
- 确认所有插件的运行时依赖版本
- 升级后立即验证常用插件命令

---

### 🟥 坑 2：回滚只回配置不回 Profile，造成半态

**时间**：2026-09-08（new-api 网关切换）
**现象**：回滚后配置是旧的，但 profile 数据是新的，两边不一致
**根因**：只回滚了 openclaw.json，忘了 profile 数据（agents/ 目录下的 SQLite）
**影响**：认证信息、会话数据与配置不匹配，问题更复杂
**修复**：重新完整回滚（配置 + profile）
**严重程度**：🔴 高危

**规避方案**：
- ✅ 回滚必须同时回：二进制 + 配置 + profile + 插件
- ✅ 使用一键回滚脚本，不手动分步操作
- ✅ 备份时完整备份所有数据目录

---

### 🟥 坑 3：用户路径混乱（root vs openclaw）

**时间**：2026-03-24（用户迁移时）
**现象**：配置在 /root/.openclaw/ 和 /home/openclaw/.openclaw/ 双轨并行，不知道哪个生效
**根因**：迁移时目录不清晰，不同用户执行命令读到不同配置
**影响**：改了配置不生效，排查困难
**严重程度**：🟡 中危

**规避方案**：
- 升级前确认当前用户：`whoami`
- 确认配置目录：`ls ~/.openclaw/`
- 全程同一用户操作，不要中途 su/sudo
- 当前环境：root 用户，配置在 /root/.openclaw/

---

### 🟥 坑 4：周复盘脚本因版本依赖问题失败

**时间**：2026-05-29
**现象**：升级后周复盘脚本执行失败
**根因**：脚本依赖的 OpenClaw API / 命令行接口有变更
**影响**：自动化任务中断
**严重程度**：🟡 中危

**规避方案**：
- 升级后验证所有依赖 OpenClaw 的脚本
- 外部脚本尽量不依赖 OpenClaw 内部 API，走 CLI 或标准接口
- 本次评估：主要自动化任务（简报、备份等）都是独立脚本，不依赖 OpenClaw 版本，风险低

---

### 🟥 坑 5：插件卸载后配置残留

**时间**：历史经验教训
**现象**：卸载插件后配置里还有残留，导致启动警告或异常
**根因**：插件卸载只删了代码，没清配置
**严重程度**：🟢 低危

**规避方案**：
- 升级后检查启动日志，有无插件相关警告
- 如有残留配置，清理后重启

---

### 🟥 坑 6：火山引擎欠费误判（非升级，但属配置变更）

**时间**：2026-09-02
**现象**：以为火山引擎欠费，实际是标准端点欠费，Coding Plan 端点正常
**根因**：测试时用错了端点，导致误判
**严重程度**：🟡 中危（差点误删配置）

**规避方案**：
- 升级后验证 provider 时，使用实际配置的端点
- 不要凭经验判断，看实际配置的 baseURL

## 二、升级前检查清单（避坑用）

执行升级前，逐项确认：

| 检查项 | 命令/方法 | 目的 |
|--------|-----------|------|
| 当前用户 | `whoami` | 确认路径一致性 |
| 当前版本 | `openclaw --version` | 基线确认 |
| Python 版本 | `python3 --version` | 插件兼容性 |
| Node 版本 | `node --version` | 运行环境 |
| 磁盘空间 | `df -h /root` | 确保升级有空间 |
| Gateway 状态 | `systemctl --user status openclaw-gateway` | 基线状态 |
| 配置目录 | `ls ~/.openclaw/` | 确认路径 |
| 备份目录空间 | 预估至少 500M | 备份需要 |
| npm 源可用 | `npm config get registry` | 升级下载需要 |
| 最近错误日志 | `tail -50 /tmp/openclaw/*.log \| grep -i error` | 排除基线问题 |

## 三、升级后验证清单（避坑用）

升级后逐项验证，全部通过才算成功：

### 基础验证
- [ ] 版本号正确：`openclaw --version`
- [ ] Gateway 运行中：`systemctl --user status openclaw-gateway`
- [ ] 端口正常监听：`ss -tlnp | grep 18789`
- [ ] CLI 命令可用：`openclaw status`
- [ ] Dashboard 可访问

### 功能验证
- [ ] 模型调用成功（发测试消息）
- [ ] 多 provider 均可用（zai / deepseek / volcengine）
- [ ] 飞书消息收发正常
- [ ] 飞书工具可用（日历、文档、任务等）
- [ ] 子代理功能正常
- [ ] 定时任务配置完整：`crontab -l`

### 日志验证
- [ ] 启动日志无 ERROR
- [ ] 运行 10 分钟无异常报错
- [ ] 无插件加载失败警告
- [ ] 内存/CPU 正常

## 四、回滚触发条件

满足以下任一条件，立即执行回滚（不要犹豫，先回滚再排查）：

🔴 **立即回滚**：
- Gateway 无法启动，端口未监听
- 飞书完全无法收发消息
- 所有模型调用均失败
- 数据丢失或配置损坏

🟡 **30 分钟内无法修复则回滚**：
- 核心功能异常
- 内存/CPU 异常飙升
- 插件大面积失效
- 定时任务无法执行

🟢 **可观察不回滚**：
- 非核心功能小问题
- 不影响业务的 UI 变化
- 日志 warning 不影响功能

---

## 五、升级黄金法则

1. **备份第一** — 没做完整备份，绝不开始升级
2. **回滚优先** — 出问题先回滚，再排查，不要在生产环境 debug
3. **完整回滚** — 二进制+配置+profile+插件，一个都不能少
4. **验证到位** — 升级后逐项验证，不靠感觉
5. **同一用户** — 全程同一用户操作，避免路径混乱
6. **留足时间** — 选业务低峰期，预留至少 30 分钟操作+回滚时间
