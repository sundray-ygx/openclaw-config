# 早间简报二次调优方案（GitHub 热榜描述升级 + AI 要闻聚合重构，待决策）

日期：2026-10-28 · 性质：规划，未改代码

## 一、需求理解

1. **GitHub 热榜**：一句话要覆盖「解决什么问题 + 应用场景 + 如何应用」+ 标注分类——当前只有 📖 首句截断，信息维度不够
2. **AI 要闻**：GitHub 只盯 openclaw 和 hermes-agent 两个项目本身的更新（issues/releases），通用仓库搜索彻底移除；新闻要做**跨源聚合突出焦点**，聚焦产品经理/创业/AI 趋势/海外新闻

## 二、数据可行性（已核实）

- 日报每项目自带「📦 分类」字段（如"AI 代理 / 输出行为约束"）——分类直接取，零成本
- 📖 段落覆盖"是什么/解决什么"，🌟 段常含"👉 应用建议"——素材齐全，但散落在多段
- 脚本有现成 LLM 通道：new-api 网关（NEWAPI_API_KEY + glm-5.3-flash），脚本历史上有 AI 摘要先例
- hermes-agent 官方仓库：NousResearch/hermes-agent（已确认存在）

## 三、方案

### 调整1：GitHub 热榜描述 → LLM 精炼
每项目把「📖 段落全文 + 🌟 段落 + 分类」喂给 glm-5.3-flash，prompt 强约束输出一句：
「【分类】解决〈什么问题〉，适用于〈场景〉，上手方式〈一句话〉」，≤80 字。
- 5 次调用 ≈ 增时 15~30 秒，成本忽略不计
- LLM 失败/超时（单条 12s 超时）→ 降级为现在的规则提取（📖 首句），绝不断链

### 调整2：AI 要闻重构
1. **GitHub 部分**：`get_github_openclaw_news()` 扩展为双仓库——openclaw/openclaw + NousResearch/hermes-agent 各取最新 issues 2 条 + release 1 条（含 Reach 正文增强）；通用搜索（hermes/openclaw/AI agent 三组仓库搜索）彻底删除
2. **新闻聚合（焦点算法）**：
   - 池子：国内 RSS×4（量子位=AI 趋势、36氪=创业、钛媒体、人人都是产品经理=产品经理）+ 海外 RSS（BBC=海外）+ 双仓库 GitHub 动态
   - 聚类：标题分词取关键词，两篇文章共享 ≥2 个关键词（或一方标题含另一方标题主要词）判为同一焦点，计数"多源命中"
   - 排序：焦点命中数 > 打分；多源命中的条目标注「🔥N源报道」
   - 出 6 条：优先多源焦点，其次单源高分；来源均衡（避免量子位独占）
3. 备选补充源（可选）：虎嗅 RSS（商业/创业向），加了更贴"创业"焦点
