# GitHub 热榜板块集成方案（TTlook111/github-trending-daily，待决策）

日期：2026-10-28 · 性质：规划，未改代码

## 一、数据源侦察结论（已核实）

- 仓库每日一份中文 Top-10 趋势分析报告，路径 `2026/MM/YYYY-MM-DD.md`（如 `2026/10/2026-10-28.md`），MIT 许可
- 每个项目结构：`### #N 仓库名` + 表格（链接/Stars(含日增)/语言/分类）+ 三段正文：「📖 项目是干什么的」「💡 可借鉴的优点」「🌟 特别亮眼」
- **关键风险**：README 明示"人工+AI 协作产出，自动化脚本开发中"——**发布时间不固定**，早报 08:00 时当天报告可能还没出；个别日期整份缺失
- 抓取通道：raw.githubusercontent.com 需走 sing-box 代理（curl `--socks5-hostname`，已验证通道可用）

## 二、集成设计

**新增板块「🔥 GitHub 热榜」**，位置：AI 要闻之后、B站精选之前。逻辑：

1. 取报告：今天 → 昨天 → 前天（逐日回退，最多 3 天，报告头部标注数据日期）
2. 解析：按 `### #N` 切分，每项目提取「项目是干什么的」段首 1-2 句（≤80 字）——天然覆盖 Boss 要的"解决什么问题、应用场景"（该段落本身就是这个结构）
3. 展示：`• [仓库名](链接) ⭐38.3k(+3.9k) Python` + 一句话描述，取 **Top 5**
4. 失败静默跳过（代理断/仓库改版不影响早报其余板块）

**不采用**的替代方案：自抓 github trending 页 + LLM 生成描述（重复造轮子，质量不如该仓库的人工+AI 深度拆解）。
