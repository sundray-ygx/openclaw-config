## 2. 方法论框架：从战略到执行

我们已有战略层方法论，本次引入执行层方法论，形成完整闭环：

```
┌─────────────────────────────────────────────────────┐
│                   方法论全景图                        │
│                                                      │
│  战略层（已有）          执行层（本次引入）              │
│  ┌─────────┐           ┌───────────┐                │
│  │ RPP      │           │ PGSAR闭环  │                │
│  │ 优先事项 │  ──→      │ P-Plan    │                │
│  │ 流程     │  拆解     │ G-Goal    │                │
│  │ 资源     │  执行     │ S-Standard│                │
│  ├─────────┤           │ A-Action  │                │
│  │ PPT      │           │ R-Review  │                │
│  │ 人       │           └─────┬─────┘                │
│  │ 流程     │                 │                      │
│  │ 技术     │                 ↓                      │
│  └─────────┘           ┌───────────┐                │
│                        │ SMART原则  │                │
│                        │ 目标验证    │                │
│                        └───────────┘                │
└─────────────────────────────────────────────────────┘
```

**简单理解**：
- **RPP+PPT** 解决"为什么做、怎么组织" — 已完成，不需要重复讨论
- **PGSAR** 解决"具体做什么、怎么衡量、怎么纠偏" — 本次研讨会的核心
- **SMART** 是目标质量检查工具 — 确保每个目标经得起推敲

---

## 3. PGSAR 闭环详解

```
    ┌──────────┐
    │ P(Plan)  │ ← 检视整体计划，确认方向
    └────┬─────┘
         ↓
    ┌──────────┐
    │ G(Goal)  │ ← SMART拆解，把大目标变成小目标
    └────┬─────┘
         ↓
    ┌──────────────┐
    │ S(Standard)  │ ← 定义"做好了"的标准，可衡量
    └────┬─────────┘
         ↓
    ┌──────────┐
    │ A(Action)│ ← 明确行动、责任人、时间
    └────┬─────┘
         ↓
    ┌──────────┐
    │ R(Review)│ ← 定期检视，红黄绿灯，偏差纠偏
    └────┬─────┘
         │
         └──→ 回到 Plan，调整优化，持续循环
```

**一句话理解**：计划 → 拆解 → 定标准 → 行动 → 检视 → 调整，循环往复。

## 4. SMART 原则：目标质量检查

每个目标必须通过5个维度的验证：

| 维度 | 问题 | 合格标准 | 不合格示例 |
|------|------|----------|-----------|
| **S**pecific | 具体做什么？交付什么？ | 有明确的交付物和范围 | "推进AI应用" |
| **M**easurable | 怎么衡量完成？ | 有量化指标和基线 | "提升效率" |
| **A**chievable | 现在能做吗？ | 信心指数≥7，或有清晰的提信心路径 | 目标远大但无实现路径 |
| **R**elevant | 和年度OKR什么关系？ | 能追溯到具体KR | 孤立任务，和目标无关 |
| **T**ime-bound | 什么时候完成？ | 有明确的截止日期和关键节点 | "尽快""年底前" |

**核心工具：信心指数**
- 每个里程碑打分 1-10
- **≥8**：目标合理，直接拆解行动
- **5-7**：有风险，需要讨论卡在哪，可能要拆分
- **<5**：目标不可行，必须重新定义或大幅拆分

## 三、各环节详细说明

### 环节一：障碍对齐

**目标**：系统性收集和分类各产线当前落地障碍，找到解法方向。

**流程**：

1. **各产线轮流呈现**（精简版：每产线3-4分钟 / 完整版：每产线5-6分钟）
   - 讲TOP3障碍，每条障碍说明：是什么、影响多大、已尝试什么、需要什么支持
   - 其他产线可补充类似经验，但**不展开讨论**（避免超时）

2. **主持人现场分类**，使用以下分类框架：

| 类别 | 说明 | 典型解法方向 | 典型责任方 |
|------|------|-------------|-----------|
| **A. 工具/平台缺失** | 基础设施不到位，想用但没工具 | 加速建设、找临时替代方案 | 综合管理部 |
| **B. 能力/技能不足** | 工具在但不会用、用不好 | 培训、布道师辅导、结对实践 | 布道师+综合管理部 |
| **C. 流程/规范阻力** | 现有流程与AI-Native冲突 | 流程适配、试点验证、分步切换 | 产线+综合管理部 |
| **D. 资源/优先级冲突** | 人不够、和其他工作排不开 | 资源协调、优先级调整、管理层决策 | 管理层 |
| **E. 目标不清晰** | 不知道具体该做什么、怎么做 | 目标拆解（环节二解决） | 产线 |

3. **快速聚类**（完整版额外环节，5分钟）
   - 跨产线共性障碍现场识别
   - 标注"2+产线共同面临"的障碍 → 提升为平台级问题，综合管理部优先处理

**产出**：障碍清单（含分类、优先级、初步解法方向、责任方）

---

### 环节二：目标拆解工作坊

**目标**：针对近期里程碑（Q2剩余+Q3初期），用SMART验证可达成性，拆出具体可执行任务。

**流程**：

1. **各产线轮流呈现**（精简版：每产线5-6分钟 / 完整版：每产线7-8分钟）
   - 展示1-2个（精简版）或2-3个（完整版）近期里程碑的SMART验证结果
   - 重点讨论信心指数<7的里程碑

2. **主持人引导讨论**，使用以下关键问题：

| 情境 | 引导问题 |
|------|---------|
| 目标模糊时 | "这个里程碑做完，你怎么知道做成了？看到什么就算完成？" |
| 信心指数低时 | "信心指数为什么不是8或9？最不确定的是什么？" |
| 行动不具体时 | "如果只做一件事来推进这个目标，你做什么？" |
| 责任人不清晰时 | "谁来做？什么时候能看到初步结果？" |
| 目标太大时 | "如果把这个目标切成两半，前半段是什么？" |
| 和OKR关联不清时 | "这个目标达成后，哪个KR会怎么变化？" |

3. **拆解深度要求**：
   - ✅ 合格：有具体行动项、有唯一责任人、有完成时间、有可交付物
   - ❌ 不合格："推进XX""加强XX""持续优化XX" — 必须继续拆

**产出**：各产线近期里程碑的SMART拆解表（含行动项）

## 六、主持人引导手册

> 以下内容供会议组织人参考，确保会议不跑偏。

### 时间管控

| 环节 | 常见超时原因 | 应对方法 |
|------|-------------|---------|
| 障碍对齐 | 某个产线展开讲细节 | "这个问题我们先记录，会后单独讨论" |
| 目标拆解 | 信心指数低的讨论过久 | "标记为会后补充，先看下一个" |
| 衡量标准 | 争论指标定义 | "先用V1，下次检视时再优化" |
| 任意环节 | 有人开始讨论具体技术方案 | "记下来，会后单独讨论" |

### 引导技巧

1. **暴露问题而非展示进度** — 如果有人开始汇报"我们做了什么"，引导到"还有什么没做、卡在哪"
2. **信心指数是好工具** — 让大家打分，数字比文字更能暴露问题。追问"为什么不是8？"
3. **具体化是核心** — "推进AI应用" → "推进什么AI应用？给谁用？什么时候能用？用到什么程度？"
4. **唯一责任人** — 不能写"团队负责"，必须落实到个人。如果没人认领，说明这个行动项还不成立
5. **避免完美主义** — 不强求一次会拆完所有里程碑，先把近期的拆到位

### 异常处理

| 情况 | 处理方式 |
|------|---------|
| 某产线完全没有准备 | 用SMART模板现场引导填写，其他产线先跳过 |
| 产线之间出现矛盾 | 记录分歧点，标记为待决策，不在会上争论 |
| 综合管理部和产线对障碍理解不一致 | 听产线的，他们是执行者，最了解实际情况 |
| 时间严重不足 | 砍掉环节三（衡量标准），作为会后异步确认 |
| 有人持续占时间 | 主持人直接打断："我们先记录，会后1v1讨论" |
