# AI-Native 落地推进研讨会 — 方案 V1.0

**日期**：2026年4月27日（周一晚）
**时长**：2.5小时
**参会范围**：无线、交换机、NMC、会议主机、IPSIP、硬件、综合管理部
**方法论**：PGSAR闭环（Plan-Goal-Standard-Action-Review）

---

## 一、会议目标

1. **对齐障碍** — 各产线明确当前TOP3落地障碍，集体诊断，找到解法方向
2. **拆解目标** — 针对近期里程碑，用SMART验证可达成性，拆出具体可执行任务
3. **建立检视** — 确定过程衡量指标和定期检视节奏，确保持续追踪

## 四、会议流程详细说明

### 环节一：障碍对齐（50分钟）

**规则**：
- 每个产线3-4分钟，讲TOP3障碍
- 主持人现场分类到5个类别：
  - **A. 工具/平台缺失** — 综合管理部跟进
  - **B. 能力/技能不足** — 布道师+培训
  - **C. 流程/规范阻力** — 流程适配
  - **D. 资源/优先级冲突** — 管理层决策
  - **E. 目标不清晰** — 环节二解决
- 其他产线可补充类似经验，但不展开讨论（避免超时）

### 环节二：目标拆解工作坊（50分钟）

**规则**：
- 每个产线5-6分钟，展示1-2个近期里程碑的SMART验证结果
- 重点讨论信心指数<7的里程碑：为什么低？怎么拆？
- 主持人引导：如果写不出具体行动，说明拆解不到位，标记为会后补充
- 没轮到的产线可旁听借鉴，不打断

**关键引导问题**（主持人用）：
1. "这个里程碑做完，你怎么知道做成了？看到什么就算完成？"
2. "信心指数为什么不是8或9？最不确定的是什么？"
3. "如果只做一件事来推进这个目标，你做什么？"
4. "谁来做？什么时候能看到初步结果？"

### 环节三：衡量标准与共识确认（30分钟）

**规则**：
- 主持人提出统一的检视节奏建议，大家快速确认或调整
- 各产线确认1-2个核心前置指标（不用多，能跟踪就好）
- 最后5分钟确认行动项

**检视节奏建议**：
| 频率 | 内容 | 参与人 | 产出 |
|------|------|--------|------|
| 每周 | 任务执行状态更新 | 产线内部 | 进度同步 |
| 双周 | 前置指标 + 障碍闭环 | 产线+综合管理部 | 红黄绿灯报告 |
| 每月 | 里程碑达成评估 | 全体 | 月度检视 |

**红黄绿灯报告**：
| 里程碑 | 🟢正常/🟡有风险/🔴卡住 | 偏差说明 | 需要的支持 |
|--------|----------------------|----------|-----------|
|        |                      |          |           |

## 六、主持人引导要点

> 以下是给会议组织人的备忘，确保会议不跑偏。

1. **障碍环节控制时间** — 每个产线严格3-4分钟，超时打断。目的是收集，不是现场解决所有问题
2. **拆解环节关注"具体"** — 如果有人说"推进AI应用"，追问"推进什么？谁做？什么时候？做到什么程度？"
3. **信心指数是好工具** — 让大家打分，数字比文字更能暴露问题
4. **不强求完美** — 本次时间紧，核心是找到方向和下一步行动，细节会后补充
5. **避免陷入技术讨论** — 有人开始讨论具体技术方案时，提醒"记下来，会后单独讨论"
6. **确保每个行动有唯一责任人** — 不能写"团队负责"，必须落实到个人

## 附录：PGSAR闭环框架说明

**执行层方法论，与战略层RPP+PPT配合使用：**

```
P (Plan)    — 整体计划（已有里程碑计划，本次检视和调整）
G (Goal)    — SMART拆解目标（本次研讨会核心工作）
S (Standard)— 定义衡量标准（前置指标 + 滞后指标）
A (Action)  — 具体行动、责任人、时间节点（任务拆解）
R (Review)  — 定期检视，红黄绿灯，偏差纠偏（双周/月度机制）
     ↑_________________________↓（持续闭环）
```

**核心思想**：
- 目标要SMART，不能模糊
- 过程要可衡量，不能到年底才发现偏差
- 检视要定期，不能等出了问题才看
- 行动要具体，不能停在"推进""加强"这种虚词上
