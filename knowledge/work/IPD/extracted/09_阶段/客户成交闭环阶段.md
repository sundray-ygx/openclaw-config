# 客户成交闭环阶段


> **版本**：V2.0（基于5月7日更新版本）
> **阶段类型**：全生命周期  
> **阶段定位**：从商机发现到项目下单，实现客户价值闭环

---

## 一、阶段概览

### 1.1 活动目的/意图

- 实现从商机到成交的**端到端闭环**
- 确保产品价值被客户认可
- 确保方案设计合理，匹配客户需求

### 1.2 子阶段划分

| 子阶段 | 核心目的 |
|--------|----------|
| 商机阶段 | 挖掘发现商机 |
| POC测试 | 负责测试，确保产品效果 |
| 售前阶段 | 工勘 + 出点位图纸 |
| 方案设计 | 出方案 |
| 商务谈判 | 商务谈判 |
| 项目下单 | 下单 |

### 1.3 关键角色

| 角色 | 说明 |
|------|------|
| 解决方案经理/销售 | 主导商机到成交的全流程 |

## 二、质量运营

### 2.1 质量风险

| 子阶段 | 质量风险 | 来源角色 |
|--------|----------|----------|
| POC测试 | 若测试效率本身很低、成本很高，可能销售不愿意做测试，也可能影响成单 | PDT经理 |
| POC测试 | 测试的方案和效果，有可能影响成单 | 业务ST团队 |
| 售前-工勘 | 工勘没做好，影响后续使用体验；对人的依赖导致的不可控 | 业务ST团队 / PDT经理 |
| 售前-点位图纸 | 点位设计有问题，影响后续使用体验，而且还不容易解决 | 业务ST团队 |
| 方案设计 | 因价格或能力原因，做了不适合客户质量要求的方案设计 | 业务ST团队 |
| 方案设计 | 售前和销售方案设计能力不足 | PDT国内市场代表 |
| 方案设计 | 不完善：标准化的设计方案（超融合场景有标准，其他场景缺失，如大型组网核心未设计双机；设备混用场景） | PDT规划代表 |
| 方案设计 | 缺失：在方案设计时，擅自修改客服的设计方案和选型，还不和客服同步核实 | PDT软件研发代表 |

### 2.2 预防措施

- 建立标准化的设计方案（扩展到更多场景）
- 加强售前和销售的方案设计能力
- 方案设计环节与客服保持同步
- 建立工勘标准和点位设计规范
