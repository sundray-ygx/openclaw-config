# SR - 服务评审系列


> **版本**：V2.0（基于5月7日更新版本）
> **阶段类型**：服务评审（Service Review）  
> **阶段定位**：确保产品的可交付性和售后保障  
> **争议升级**：PDT经理最终决策

---

## 一、系列概览

### 1.1 SR系列定位

SR系列是IPD流程中的**服务能力评审体系**，确保产品的可服务性需求得到满足，服务上市计划合理，服务装备和工具就绪，能够实现服务侧"上市即上量"。

### 1.2 SR系列阶段划分

| 阶段 | 名称 | 所属DCP阶段 |
|------|------|-------------|
| SR1&2 | 服务计划 | DCP4（Beta发布） |
| SR3 | 服务预发布 | DCP4（Beta发布） |

### 1.3 特殊说明

- PDT供应链代表在SR阶段**先不参与**（需要返修/备机等资源时，客服直接协同供应链即可）

---

## 二、SR1&2 - 服务计划

### 2.1 活动目的/意图

- 把关服务侧**可服务性需求**是否合理完整，且与版本主场景与客群匹配
- 把关**服务上市计划**（含装备、服务产品、关键beta方向等）合理性
- 能实现服务侧"**上市即上量**"
- 把关客户成功策略设计和计划的合理性
- 把关整体服务计划和服务代表的协同分工明确（特别是线上和线下的服务模式协同设计）

### 2.2 准入准出

|------|----------|----------|----------|------|
| PDT经理 | 产线项目主管 | **评审表决** | - | - |
| PDT规划代表 | 产线规划 | **建议参评** | - | - |

- 服务上市计划合理性

## 三、SR3 - 服务预发布

### 3.1 活动目的/意图

- 把关**可服务性需求、新功能、服务装备**的CleanRoom验收结果符合标准与预期
- 把关**服务beta目标与计划**，可协同研发面向客户启动beta验证
- 把关客户服务设计的各项工作已经完成准备
- 把关**服务旅程**能跑通，可以开始面向客户做beta验证
- 把关服务材料的完整性（无被遗漏或未被考虑到的）和计划合理性
- 把关产品可服务性需求以及相关服务工具的验收结果
- 把关服务装备质量标准的达成情况，确保其能满足版本预发布的需要

### 3.2 准入/准出条件

| 角色 | 对应岗位 | 参与类型 | 核心职责 | 权利 |
|------|----------|----------|----------|------|
| PDT经理 | 产线项目主管 | **评审表决** | - | - |
| PDT规划代表 | 产线规划 | - | - | - |
| PDT软件研发代表 | 产线架构师 | **评审表决** | 把关服务材料的完整性和计划合理性 | 对本技术评审节点做评审表决 |
| PDT服务代表 | 客服交付中心主管 | **发起** | 主导SR3活动的会议材料准备和组织；主导SR3内容前置检视，把关质量 | 基于SR3对准备工作进行分工；识别问题推动解决 |
| PDT供应链代表 | 供应链代表 | **先不参与** | - | - |
| 服务代表扩展团队 | 交付专家 | **评审表决** | 把关可服务性需求/新功能/服务装备的验收结果 | 对本技术评审节点做评审表决 |

### 3.4 质量关注点

- CleanRoom验收结果是否达标
- 服务beta计划是否可执行
- 服务装备质量是否满足预发布需要
- 服务旅程是否能跑通

## 四、SR系列发起人职责详解

### 4.1 发起人（PDT服务代表）职责

1. 主导SR活动的会议材料准备和会议组织
2. 主导对SR内容进行会议前置的检视，把关质量
3. 对SR的顺利通过负责，最终能有效支撑项目价值与可服务性的顺利交付
4. 基于SR对准备工作进行分工
5. 识别问题，推动分工成员解决
