# DCP2-2 - 立项决策（charter）


> **版本**：V2.0（基于5月7日更新版本）
> **阶段类型**：DCP决策评审  
> **阶段定位**：完成charter开发，确定产品构想和投资回报  
> **前置阶段**：DCP2-1  
> **组织模式**：以CDT团队进行活动

---

## 一、阶段概览

### 1.1 活动目的/意图

- 完成charter开发（如硬件规格书&选定制造商）
- 确定产品构想的可选架构及技术可行性
- 完成市场分析、产品概念、竞争分析、盈利模式分析
- 确定投资回报率等财务指标

### 1.2 阶段定位

DCP2-2是立项决策的核心环节，以CDT团队活动，产出完整的charter文档。此阶段需要各领域深度参与，完成从市场分析到技术方案的全面论证。

### 1.3 时效性要求

- 立项完成两周内

## 二、准入准出

> 来源：04_准入准出全景表.md

### 2.1 准入条件

| 角色 | 准入条件 |
|------|----------|
| PDT经理 | - |
| PDT规划代表 | 规划基调评审结果（邮件）+ CDT开工会 |
| PDT软件研发代表 | 规划基调评审结果（邮件）+ CDT开工会 |
| PDT国内市场代表 | CDT开工会 |
| PDT国际市场代表 | CDT开工会 |
| PDT服务代表 | 规划基调评审结果（邮件）+ CDT开工会 |
| PDT硬件研发代表 | 规划基调评审结果（邮件）+ CDT开工会 |
| PDT供应链代表 | 变更决策评审 + 规划基调评审结果（邮件）+ CDT开工会 |
| 产品线ST代表 | 规划基调评审结果（邮件）+ CDT开工会 |

### 2.2 准出标准

**PDT规划代表**（核心准出）：
1. 宏观市场和行业发展带来的新机会分析
2. 确定目标细分市场和客户画像
3. 目标细分市场的特征定义和应用场景描述
4. 目标客户的业务场景、痛点和期望分析（买点、卖点），提供客户画像的原型验证结果
5. 新产品给客户带来的价值定义以及竞争力进行量化（TCO/TVO）分析，确定价值可变现的窗口期
6. 在每个目标市场，公司当前与期望的市场定位、意图对比
7. 产品生命周期
8. 产品规划表&硬件规格书
9. 汇总完成财务指标分解计算结果，给出合理的ROI分析

**PDT软件研发代表**（技术分析）：
- 关键技术战略控制点分析
- 竞争对手技术发展趋势和关键实现路径
- 技术分析结论和预研计划
- 产品技术方向和预研效果评估
- 质量风险评估和质量策略制定

**PDT硬件研发代表**：硬件可行性分析报告 + 预研结果评估

**PDT国内/国际市场代表**：
1. 针对核心价值和用户画像的实际验证结果
2. 验证规划的用户画像是否为市场增长点
3. 价值通路可行性分析
4. 市场容量分析、竞争格局和策略、定价策略、销量分析

**PDT服务代表**：标准化交付方案（含交付和售后痛点分析、服务目标、售后SLA方案、维保方案）

**PDT供应链代表**：
1. SKU效率分析
2. 制造落地方案
3. 合作伙伴/合作模式/合作策略
4. 采购方案
5. 采购计划

**产品线ST代表**：
1. 决策结果（依据、charter文档、签字表）邮件通知

### 2.3 关键交付物

- charter文件 + 签字表
- 产品规划表&硬件规格书
- 硬件可行性分析报告
- ROI分析报告
- 标准化交付方案

## 三、权责决策

### 3.1 决策角色矩阵

> 来源：02_决策全景表.md、03_权责全景表.md

| 角色 | 对应岗位 | 参与类型 | 职责 | 权利 |
|------|----------|----------|------|------|
| PDT经理 | 产线项目主管 | **共同开发&评审表决** | 参与DCP2-2立项评审，对立项的目标、用户需求设计、技术需求设计、计划合理性、风险应对计划等进行把关；对立项业务成功整体负责；负责研发投入资源需求分析 | 站到项目整体视角提出合理建议，行使表决权 |
| PDT规划代表 | 产线规划 | **评审表决** | 负责整体拉通市场分析、产品概念、应用场景、竞争分析、盈利模式分析；负责产品构思和需求包定义；对Charter细分市场需求负责；从公司利润率目标分解目标成本；为客户对价值的认可度负责 | 推动相关方闭环评审问题；向上级主管反馈获取支持 |
| PDT软件研发代表 | 产线架构师/TL | **共同开发&评审表决** | 对charter产品构想的可选架构及技术可行性负责；评估技术准备度；分析竞争对手技术；识别技术风险和预研任务 | 对本DCP节点做评审表决 |
| PDT国内市场代表 | 国内产品运营主管 | - | 把关本次立项的需求和价值符合市场预期；把关市场营销目标和策略能支撑价值顺利上市 | 对本DCP节点做评审表决 |
| PDT国际市场代表 | 国际产品运营主管 | - | 同国内市场代表 | 对本DCP节点做评审表决 |
| PDT服务代表 | 客服交付中心主管 | **评审表决** | 把关可服务性需求、关键价值符合服务预期；把关服务目标和策略能支持价值交付 | 对本DCP节点做评审表决 |
| PDT硬件研发代表 | 硬件研发主管 | - | 明确客户/市场选择、商业价值、价值主张、技术/成本可行 | 对立项结果行使表决权 |
| PDT协作部门 | 协作部门 | - | 同规划代表和研发代表 | - |
| 产品线ST代表 | 产线主管 | - | 代表体系做业务评审，检视是否支撑商业目标可达，把关风险 | 基于商业投资决策视角表决 |

### 3.2 决策机制

- **决策原则**：全票通过制
- **争议决策**：PDT经理最终决策
- **有效性评级**：研发PMO项目计划评级

| 角色 | 质量风险 |
|------|----------|
| PDT经理 | 缺陷预防计划；项目计划未预留风险周期或按需发货，在应对上攻客户时导致风险过高 |

- 制定缺陷预防计划

## 五、流程活动

### 5.1 主要活动步骤

1. 基于规划基调评审结果，召开CDT开工会
2. 各领域按CDT分工开展charter开发工作
3. PDT规划代表拉通市场分析、产品概念、竞争分析
4. PDT软件研发代表完成技术分析和预研评估
5. PDT硬件研发代表完成硬件可行性分析
6. PDT市场代表完成市场验证和销量分析
7. PDT服务代表完成标准化交付方案
8. PDT供应链代表完成采购和制造方案
9. 汇总完成charter文档
10. 组织charter评审会议
11. 评审表决通过后进入DCP3

### 5.2 关键检查点

- [ ] 市场洞察和客户画像是否充分
- [ ] 技术可行性是否确认
- [ ] ROI分析是否合理
- [ ] 各领域charter开发内容是否闭环
- [ ] charter文件+签字表是否完成
