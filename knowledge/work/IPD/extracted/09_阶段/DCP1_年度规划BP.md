> **版本**：V2.0（基于5月7日更新版本）
> **阶段类型**：DCP决策评审  
> **阶段定位**：将产品战略解码为年度可执行的目标和计划  
> **前置阶段**：DCP0  
> **输出文档模板**：XXX产品线-SPBP战略规划(XX年度)（DCP1部分）  
> **详细文档**：08_IPD流程阶段全景图.md

## 一、阶段概览

### 1.1 活动目的/意图

- 将DCP0的战略方向**解码为年度可执行的目标和计划**
- 完成年度目标复盘和新目标制定
- 确定关键举措、里程碑和产品路标
- 确定立项和预研计划
- 明确组织建设和投资布局
- 识别和消除关键风险

### 1.2 阶段定位

DCP1 对应 SPBP 中的"**年度规划解码**"部分。基于DCP0确定的战略方向，制定年度落地计划，各PDT角色开始介入提供各领域视角的输入。

DCP1 的核心是回答：
1. **年度目标是什么**（OKR解码）
2. **怎么做**（关键举措 + 里程碑 + 产品路标）
3. **需要什么保障**（组织 + 投资 + 协作 + 风险消除）

### 1.3 时效性要求

- 根据BP路标定义
- 产品战略确定后需尽快推动立项

## 二、SPBP 文档结构（DCP1 部分）

> 来源：XXX产品线-SPBP战略规划(XX年度)-V3.8-2025版.docx

### 2.1 年度目标复盘和制定

#### 2.1.1 上一年度目标复盘

| 复盘维度 | 内容 |
|----------|------|
| 目标 | 当年OKR目标 |
| 结果达成简述 | 实际达成情况 |
| 关键问题（根因分析） | 未能达成的原因 |
| 好的经验总结 | 可复用的成功经验 |
| 改进举措 | 针对问题的改进方案 |

#### 2.1.2 新年度目标制定

**目标结构（OKR）**：

| 目标 | 说明 |
|------|------|
| **O1 业务目标** | 聚焦目标战场和行业，构建销售机制，实现业务规模增长（含新签订单、整体订单目标） |
| **O2 业绩目标** | 销售业绩复合增长率和年度金额目标 |
| **O3 组织建设目标** | 面向一线作战，组织战斗能力提升（TL责任田、特性Owner、解决方案拓展等） |
| **O4 质量改进目标** | 质量目标服务于战略及目标客户，不只是改BUG |

**质量目标定义指引**：
1. **满意度目标**：定义满意度目标（分H1/H2），TOP N根治/下降目标
2. **版本质量**：0召回，重点/主流发货版本问题率目标
3. **客户侧修复目标**：基于基线质量提升，对客户端修复的目标
4. **通用质量提升**：网上问题减少、根查率、CTI耗时TOP1、版本DI值、质量基线演进
5. **竞争力提升目标**：VoC感知的竞争力目标（分H1/H2）

### 2.2 关键举措和里程碑

#### 2.2.1 关键举措

- 围绕各OKR目标制定关键举措（含里程碑时间点）
- 任务不能只包括产研，需考虑端到端（产研、市场、MO、客服、协作部门）

#### 2.2.2 各战场举措及里程碑

- 围绕各战场业务成功梳理关键任务和里程碑
- 需考虑端到端里程碑

#### 2.2.3 产品质量提升详细举措及里程碑

**质量规划要求**：
- 质量规划部分**必须与服务代表、质量主管/VOC代表对齐**
- 围绕各质量属性的底线要求与当前满足情况的差距定义改进目标
- 包含：须解决的产品关键质量问题 + 各质量属性改进目标

### 2.3 产品路标和立项计划

#### 2.3.1 产品路标（解码更新版）

- 将里程碑点分拆的检视目标合入产品路标
- 分拆山头战役内容
- 需包含TopN问题的改善路标
- 需考虑公司常态化发布节奏（2月渠道大会、8月创新大会）
- 结论要和市场行销管理团队对齐

#### 2.3.2 立项和预研计划

| 计划类型 | 说明 |
|----------|------|
| **立项计划** | 版本计划（配套产品包含组件及装备）+ 上市计划；主要产品每年最多2个大版本 |
| **预研计划** | 和立项相关的技术预研、协作方管理 |

**立项关键要求**：
1. 产品战略确定后尽快推动立项
2. 明确哪些立项需上ST（BG业务管理团队评审），哪些在产线经营团队评审
3. 产线主管任命立项负责人，后续由立项负责人推动

### 2.4 协作需求

| 协作类型 | 内容 |
|----------|------|
| BG内部门协作 | 版本配合、人力需求、资源需求 |
| 市场需求 | 与市场团队对齐 |
| 其他BG/产线诉求 | 跨产线协作 |

### 2.5 组织建设和投资地图

#### 2.5.1 产线投资地图

| 维度 | 说明 |
|------|------|
| 总体人力投入 | 关键人才（架构师、规划、TL、T6+专家）投资布局方案 |
| 投资分类 | 业务方向投资 + 质量投资 + 经营性投资（技术支持/定制/提效/预研等） |
| 结构合理性 | 开发测试比、干部比例、专家比例、BG和研发比 |
| 特殊岗位 | 不要让特殊性岗位成为业务瓶颈 |
| 外包使用 | 外包专岗化，避免混编 |

#### 2.5.2 组织建设关键任务

**方法论**：三看（看过去、看未来、看外部）→ 一定（关键任务）→ 再展开（组织、人才、文化氛围）

1. **三看**：从业务出发识别组织建设的需求和挑战
2. **一定**：聚焦最需要构建和增强的组织能力
   - 重要性高：不构建则业务目标达不成
   - 有杠杆效果：从根本上解决问题

### 2.6 关键风险消除计划

- 列出业务成功端到端主要风险及对应的消除计划
- 包含：风险描述、风险等级、应对措施、计划完成时间

## 六、流程活动

### 6.1 主要活动步骤

1. **上年度复盘**：各OKR目标复盘（达成、问题、经验、改进）
2. **新年目标制定**：制定年度OKR（业务+业绩+组织+质量）
3. **关键举措梳理**：围绕各战场梳理端到端举措和里程碑
4. **质量提升计划**：与服务代表/VOC对齐，制定质量改进举措
5. **产品路标制定**：解码更新产品路标，明确立项计划
6. **协作需求对齐**：与各协作部门对齐需求和计划
7. **组织建设规划**：投资地图 + 关键任务
8. **风险识别消除**：端到端风险清单和消除计划
9. **组织DCP1评审**：各PDT角色评审表决
10. 评审通过后进入DCP2-1

### 6.2 关键检查点

- [ ] 上年度复盘是否充分（根因分析到位）
- [ ] 新年OKR是否与DCP0战略对齐
- [ ] 关键举措是否端到端（不只产研）
- [ ] 质量规划是否与服务代表/VOC对齐
- [ ] 产品路标是否包含TopN改善和发布节奏
- [ ] 立项计划是否明确（哪些上ST、哪些在产线）
- [ ] 协作需求是否已达成一致
- [ ] 组织建设是否聚焦关键能力
- [ ] 关键风险是否有消除计划
