# 知识库分类归档指南

> 本文档定义知识库的分类原则和归档规则。同步到 NAS 后，Hermes Agent 应依据本文档执行知识库的分类归档。
>
> 最后更新：2026-05-17

---

## 一、分类原则

### 1.1 MECE 原则

知识库按 **"生活领域"** 作为一级分类维度，确保：
- **互斥（Mutually Exclusive）**：每个文件只属于一个一级目录
- **完整（Collectively Exhaustive）**：所有知识都有归属

### 1.2 五个一级领域

| 一级目录 | 定义 | 包含什么 | 不包含什么 |
|----------|------|----------|------------|
| `work/` | 公司职场相关 | AI-Native 落地推进、IPD 流程、OKR 体系、BP 战略规划、部门管理 | 个人技术学习、个人项目 |
| `tech/` | 个人技术知识 | 开发工具、基础设施运维、数据管道、技术研究 | 公司流程制度、公司战略 |
| `life/` | 个人生活 | 财务管理、租金账单、个人副业项目 | 工作事务、纯技术文档 |
| `reflection/` | 元认知与方法论 | 每日反思归档、改进方法论、模式识别 | 具体的技术/工作内容 |
| `security/` | 安全（跨领域） | 安全审计报告、安全事件记录 | 普通技术文档（归入 tech/） |

### 1.3 判断优先级

当文件涉及多个领域时，按以下优先级判断归属：

```
security > reflection > work > life > tech
```

- 涉及安全事件 → `security/`
- 纯反思/方法论，无具体领域内容 → `reflection/`
- 公司相关 → `work/`
- 个人生活相关 → `life/`
- 技术知识 → `tech/`

## 三、归档操作规则

### 3.1 文件命名规范

| 文件类型 | 命名格式 | 示例 |
|----------|----------|------|
| 日期相关 | `YYYY-MM-DD-title.md` | `2026-05-08-tech-lessons.md` |
| 常驻文档 | `topic-name.md`（小写短横线） | `frp-config.md` |
| 账单/财务 | `项目编号-YYYY-MM.*` | `13b402-2026-04.json` |

### 3.2 自动归档文件处理

每日反思脚本会生成"记忆归档"文件（含 YAML front matter + tags）：

**处理规则**：
1. 如果是反思/元认知内容 → `reflection/daily/YYYY-MM-DD-reflection.md`
2. 如果是具体领域知识 → 按领域归入对应目录
3. inbox 文件应在 24 小时内完成分类

### 3.3 版本文件处理

工作文档常有多个版本（V1.0、V2.0、backup 等）：
- 保留最新 2 个版本，更早的删除或移入 `_archive/` 子目录
- 文件名中保留版本号：`方案V2.0.md`

### 3.4 目录命名规范

- 一级/二级目录：**小写英文 + 短横线**（`ai-native`、`dev-tools`）
- 三级及以下工作目录：允许中文（`落地推进研讨会`、`产线落地计划`）
- 每个目录可包含 `README.md` 说明该目录用途

## 四、什么不该放知识库

| 类型 | 应该放哪 | 原因 |
|------|----------|------|
| 运行时脚本 | `scripts/` | 脚本是可执行代码，不是知识 |
| 日报/周报 | `archive/daily/` `archive/weekly/` | 报告是归档，不是知识 |
| 记忆日志 | `memory/YYYY-MM-DD.md` | 日志是记忆系统的一部分 |
| 敏感信息 | 不存储 | 密码、密钥、Token |
| 大型二进制 | `archive/` 或不存储 | 视频、大型 PDF 等 |

## 七、同步说明

本知识库会同步到 NAS 环境。同步时注意：
1. **只同步 knowledge/ 目录**，不同步 scripts/、memory/ 等
2. **删除同步中的冗余文件**，以主仓库（本机）为准
3. 同步后 Hermes Agent 应读取本文档理解分类规则
4. 如 NAS 端有新增知识，按本文档规则分类后提交回主仓库
