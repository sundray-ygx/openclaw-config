## 三、详细诊断

### 1. 🔴 早间简报 — AI 摘要静默失败 4 个月（P0）

**证据**
- `/var/log/morning-briefing.log` 中 `summarize 错误: [Errno 2] No such file or directory: 'summarize'` 出现 **985 次**
- `AI摘要生成完成: 0/9 篇成功` 出现 **108 次**，仅 1 次 9/9 成功（手动运行环境）
- 每日简报仍正常发送飞书（RSS 摘要降级兜底），**用户无感知**

**根因**
- `morning_briefing.py` 第 764 行：`cmd = ["summarize", url, ...]` 使用相对命令名
- cron 环境 PATH 默认不含 `/usr/local/bin`（summarize 所在目录）→ subprocess 抛 FileNotFoundError
- 脚本降级逻辑（fallback RSS 摘要）掩盖了故障，无任何告警

**影响**: 简报 AI 摘要功能失效 108 天；当前仅 RSS 首句摘要，信息密度和质量下降

**修复方案**（二选一）
- 方案 A（推荐，改动最小）：脚本中改用绝对路径 `/usr/local/bin/summarize`
- 方案 B：crontab 行首增加 `PATH=/usr/local/bin:/usr/bin:/bin`（影响所有任务，需评估）

> ⚠️ 修复后需验证 `VOLCENGINE_API_KEY` 在 cron 环境中可用（summarize 脚本从环境变量读取 key，cron 环境无该变量时 AI 调用仍会失败——需将 key 写入脚本或 crontab 环境变量）

---

### 2. 🔴 GitHub 每日同步 — 实际失效 12 天（P0）

**证据**
- git log：7/31 之后**零提交**（8 月 Auto sync 提交数 = 0）
- OpenClaw cron runs：每晚 23:30 触发，status 全部 ok，但 durationMs 仅 8~213ms（= 事件投递耗时，非脚本执行）
- cron-exec-log.jsonl 记录停在 7/31
- 当前工作区有 6 个文件未提交变更（memory 状态文件），说明同步确实未执行

**根因**
- 该 cron 是 `systemEvent` 模式：调度器只把文本注入主会话，**依赖 agent 主动响应并执行脚本**，无执行保证、无失败反馈
- `lastRunStatus: ok` 只表示"事件投递成功"，与脚本是否执行无关 → 假阳性监控
- 附带风险：sync 脚本 `git commit || true` 会吞掉 commit 失败（如 pre-commit 钩子拦截），继续 push 旧状态

**影响**: 配置备份到 GitHub 中断 12 天；一旦本地磁盘故障，配置丢失无法恢复

**修复方案**
- 方案 A（推荐）：改为 **isolated agentTurn** cron，prompt 直接执行 `bash /root/.openclaw/workspace/scripts/sync-to-github.sh`，失败时 announce 告警
- 方案 B：从 crontab 直接调度脚本（脱离 OpenClaw），最可靠但绕过 agent 监控
- 附加：脚本中 `git commit || true` 改为失败即退出并告警（`set -e` 已开启但被 `|| true` 绕过）

## 执行摘要

**OpenClaw 本体存在 2 个 P0 级带病运行问题：模型认证配置错配 + 后台 LLM 调用循环失败。** 这些是上轮未覆盖的盲区——业务层已修复，但承载业务的 OpenClaw 自身在“带病运行”：每次 LLM 调用都先白失败 2 次，后台任务（heartbeat 等）周期性超时失败。

| 优先级 | 问题 | 影响 |
|--------|------|------|
| 🔴 P0 | **模型认证错配**：primary=volcengine 但无 API key | 每次 LLM 调用先失败 2 次（volcengine×2）才 fallback 到 deepseek；延迟 + 失败面 |
| 🔴 P0 | **后台 LLM 调用 122s 超时循环**（每 1-2 小时一次） | heartbeat/embedded 任务全失败 → heartbeat 维护停滞 13 天的根因 |
| 🟡 P1 | **cron 结果投递失败**（上轮改造缺陷） | GitHub 同步执行成功但结果未送达（consecutiveErrors=2） |
| 🟡 P1 | heartbeat 带病运行 | 配置存在（60m）但每次处理必失败，维护逻辑从未执行 |
| 🟡 P1 | openclaw-lark 插件契约错误 ×36 | 插件 2026.3.15 与核心 2026.5.28 契约不匹配（功能仍可用） |
| 🟢 P2 | 版本 2.5 个月未更新；service PATH 非标准；bailian 占位符残留 | 兼容性风险、启动配置不规范、死配置 |

## 关键证据链

### P0-1 模型认证错配（root cause）
```
openclaw.json agents.defaults.model:
  primary:   volcengine/doubao-seed-2-0-pro-260215   ← 无 key
  fallbacks: [volcengine/ep-20260529105255-qgflf,     ← 无 key
              deepseek/deepseek-v4-flash]             ← 有 env key，间歇超时

auth-profiles.json 实际只有: zai:default (33838b***)   ← 唯一有效认证
```
- `VOLCENGINE_API_KEY` 在 openclaw.json 的 `env` 字段（供脚本用），**模型层不读 env，读 auth store** → volcengine 永远失败
- 后果：**每次用户消息/任务** 先报 2 次 `No API key found for provider "volcengine"`，再 fallback 到 deepseek 成功；后台任务则叠加超时风险
- MEMORY.md 记载 5/8 “系统性切换至 zai/glm-5”，但现配置 primary=volcengine → **配置漂移**，与历史决策不符

### P0-2 后台 LLM 超时循环（heartbeat 停滞根因）
```
01:04 / 03:04 / 05:04 / 07:04 / 08:04 / 09:04 / 10:04 / 11:04  （今天 8 次）
Embedded agent failed before reply: All models failed (3):
  volcengine/doubao-…: No API key          (auth)
  volcengine/ep-…:     No API key          (auth)
  deepseek/v4-flash:   LLM idle timeout (120s)  ← 卡死
```
- 每 1-2 小时触发一次，每次卡 **122 秒**，三模型全失败
- **heartbeat 机制本身正常**（11:32:59 `heartbeat: started`，配置 60m），但其 LLM 调用必失败 → 维护逻辑（cron 健康检查/记忆维护等）从未执行 → state 停在 7/31
- deepseek 间歇 120s 无响应：疑与请求上下文大小（dreaming 输入大量记忆）或 API 波动有关，待修复模型链后观察

### P1-1 cron 投递缺陷（上轮改造遗留）
```

consecutiveErrors: 2, lastRunStatus: error
```
- 上轮改 isolated agentTurn 时 delivery 只设 `mode: announce`，未指定 channel/to → 默认投飞书但缺 target → **执行成功（git 已提交 4f6f6bf）但结果丢失**
