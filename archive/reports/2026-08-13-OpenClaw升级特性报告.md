# OpenClaw 升级特性报告

**版本对比**: 2026.5.28（升级前）→ 2026.7.1-2（升级后）
**报告日期**: 2026-08-13
**数据来源**: GitHub Releases 官方变更日志（12 个稳定版本）

---

## 一、升级概况

### 版本路径

本次升级跨越约 2 个月、**10 个稳定版本**，核心路径：

```
2026.5.28 ─→ 6.1 ─→ 6.5 ─→ 6.6 ─→ 6.8 ─→ 6.9 ─→ 6.10 ─→ 6.11 ─→ 7.1 ─→ 7.1-1 ─→ 7.1-2
(5/30)     (6/3)  (6/9)  (6/12) (6/16) (6/21) (6/24) (6/30)  (7/13) (8/4)     (8/4)
```

另有并行分支 **extended-stable 线（6.34，8/8）**，主打安全修复与运行韧性——虽然本次未走这条线，但其中多项能力（provider fallback、渠道恢复、CVE 修复）已合并进 7.1 主线。

### 一句话总结

> 这是一次「**大版本升级**」：从 6 月的稳定性修补，到 7.1 的全面重构（Control UI、模型接入、调度、安全、插件生态），OpenClaw 从"能用的助手框架"进化到"可日常重度依赖的自动化平台"。

## 三、重点特性详解（是什么 / 场景 / 怎么用）

### 1. 🖥️ Control UI 全面重做（7.1）

**是什么**: 网页控制台从"聊天窗口"升级为"工作台"——会话可并排组织，新增 live Tasks（实时任务面板）、清晰的用量/费用视图、文件/下载管理、设备配对、审批流，Gateway 健康状态直接显示在对话旁。

**应用场景**:
- 同时跑多个任务（如简报生成 + 数据巡检），并排查看进度而不是翻聊天记录
- 老板要查"这个月 AI 花了多少钱"→ 用量视图直接看

**怎么用**: 浏览器打开 `http://<服务器>:18789`，升级后界面自动生效，无需配置。本机 18789 端口仅 loopback 访问，安全性不变。

---

### 2. ⚡ 自动快速模式 `/fast auto`（6.10）

**是什么**: 短对话自动用快模型（低推理档）快速响应；长任务或需要 fallback 时才回到正常模式——**按需分配算力，省 token**。

**应用场景**: 日常问答、快速指令（"看看磁盘"、"简报发了没"）用快模型秒回；深度分析（写报告、代码审查）自动回到完整模型。

**怎么用**:
```
/fast auto          # 开启自动档
/fast on            # 强制快速
/fast off           # 关闭（回到默认模型）
```
> 💡 对我们环境的建议：我们的模型链是 primary=zai/glm-5 + fallback=deepseek。可以给高频轻量任务（heartbeat 巡检、cron 状态检查）配 fast 档用 deepseek-v4-flash，降本明显。

---

### 3. 🤖 模型与 Provider 增强（7.1 / 6.8 / 6.34）

**是什么**:
- **新模型接入**: GPT-5.6、Tencent Hy3、Meta Muse Spark 1.1、GLM-5.2、Claude Haiku 4.5 等进目录，模型 ID 规范化
- **Provider fallback 韧性**（6.34）: 某个 provider 失败时自动切换备用，不再静默中断任务
- **认证失败容错**（6.1）: auth-profile failover——多个认证配置间自动切换

**应用场景**: 我们已经在用！本次巡检就是靠 fallback 韧性受益——火山引擎欠费 403 时自动切 deepseek，AI 摘要 108 天故障的根因就是缺这个能力。

**怎么用**（openclaw.json）:
```json
"model": {
  "primary": "zai/glm-5",
  "fallbacks": ["deepseek/deepseek-v4-flash", "volcengine/doubao-seed-2-0-pro-260215"]
}
```
> 我们已配置此结构。火山引擎充值后，三路 fallback 全链路可用。

---

### 4. 🔄 运行稳定性（6.1 / 6.11 / 7.1）

**是什么**:
- **中断恢复**: 工具调用被打断（如网关重启）后自动恢复，不丢任务
- **会话/内存连续性**: compaction（上下文压缩）后使用、会话历史修复、QMD 内存搜索更稳
- **Gateway 崩溃不再无限重启**（7.1）: 反复失败的网关进入"稳定修复路径"，而不是无限重启空转
- **auth 存储升级 SQLite**（7.1/6.5）: 认证配置从 JSON 迁移到 SQLite，升级/重启更安全（cron JSON 也会先迁移再运行）

**应用场景**: 本次升级实操中我们直接踩到——升级后 gateway 因新旧 systemd 服务冲突反复重启，正是 7.1 的"稳定修复路径"机制帮助我们定位（code 78 主动退出防死循环），最终通过 `OPENCLAW_NO_RESPAWN=1` + 清理残留 service 彻底解决。

**怎么用**: 无需手动操作，升级即生效。

---

### 5. 🛡️ 安全加固（6.5 / 6.6 / 6.34）

**是什么**:
- **安全边界 fail-closed**: transcript（会话记录）、sandbox（沙箱）、MCP、浏览器、渠道、exec 审批路径，默认拒绝而非默认放行
- **5 个依赖 CVE 修复**（6.34）: brace-expansion、PostCSS、fast-uri、ip-address、Undici
- **凭据保护**: 密码/token 不再出现在日志、账户 URL、摘要中；service env 占位符不掩码密钥的 bug 修复
- **插件/skill 治理**（6.1）: Skill Workshop 提案审批流、插件契约验证、危险代码扫描

**应用场景**: 我们环境有真实风险敞口（frps 弱口令、sing-box 开放代理——见巡检报告第十一章），OpenClaw 自身的安全加固保证了即使被扫描，18789 端口的会话数据、密钥不会泄露。**但网络层风险仍需按报告建议处理**。

**怎么用**: 升级即生效。`openclaw doctor` 可审计配置安全状态。

---

### 6. 📨 渠道与投递增强（6.8 / 6.9 / 6.11）

**是什么**:
- Telegram/WhatsApp 富文本（表格/列表渲染）、图片文档、进度条、失败重试
- 渠道投递韧性：重连、幂等确认（不重复发送）、pending 消息恢复
- Slack 线程/卡片/身份/去重改进

**应用场景**: 我们主要用飞书（openclaw-lark）。虽然这些改进聚焦 Telegram/Slack，但底层投递机制（重试、幂等、恢复）对飞书同样生效——**本次 cron 投递目标修复（announce → feishu 直达）就是依赖这套机制**。

**怎么用**: 渠道配置不变，升级自动获得韧性。投递异常时 OpenClaw 会重试而不是丢消息。

---

### 7. ⏰ 调度与自动化（7.1 / 6.5）

**是什么**:
- **定时任务"变化才唤醒"**: cron 任务可配置为仅在条件变化时触发（如"磁盘超过 85% 才告警"），避免空跑
- **cron JSON 存储迁移**: 升级时任务数据先迁移再运行，不丢任务
- **远程浏览器配对**（7.1）: 已登录的浏览器标签可远程操作，下载安全保存
- **工作区终端**（7.1）: web/iOS/Android 可访问受保护的终端

**应用场景**: 我们的 GitHub 每日同步（23:30）在本次升级中完成投递链路修复；"变化才唤醒"可用于租金提醒（每月 25/27 日）+ 条件触发的磁盘告警，减少无意义执行。

**怎么用**: cron 配置支持 trigger 脚本做条件门控（只有返回 fire:true 才执行）。我们的 GitHub 同步已用 isolated agentTurn 模式，就是这个机制的受益者。

### 8. 🧩 插件生态（6.1 / 6.9 / 7.1-1/2）

**是什么**:
- 官方插件独立 npm 发布，插件安装/更新/发现/诊断规范化
- **7.1-2 修复 npm 插件更新兼容**（接受新版 npm 的 singleton 元数据）——我们的 openclaw-lark 2026.7.16 正是靠这个机制升级成功的
- Skill Workshop：skill 变更走提案→审批→应用的正式流程

**应用场景**: 本次升级 openclaw-lark 从 2026.3.15 → 2026.7.16，契约错误从 36 次降到 0——这就是插件生态修复的直接收益。

**怎么用**: `openclaw plugins list` 查看插件健康，`openclaw plugins update <name>` 更新。插件状态已迁 SQLite，`openclaw doctor` 可诊断。

### 9. 💻 编码集成（7.1 / 6.9）

**是什么**: `openclaw attach` 让 Claude Code（或 Codex）临时获得指定会话的访问权；Codex 获得自动插件审批、GPT-5.3 Spark OAuth 路由、remote-node exec。

**应用场景**: 把 OpenClaw 管理的项目上下文（会话、文件、记忆）交给编码 Agent 做代码任务，完成后收回——适合研发管理场景下"让 AI 助手 + 编码 AI 协作"。

**怎么用**: 在编码工具中执行 `openclaw attach <session-id>`，按提示授权，用完自动断开。

## 五、配置与行为变化提醒（升级后必读）

1. **auth 存储已迁移 SQLite**: `auth-profiles.json` → SQLite。旧 JSON 已备份（`.sqlite-import.*.bak`），确认无误后可删。
2. **bundledDiscovery=compat**: 旧版 `plugins.allow` 语义变化，doctor --fix 已自动迁移为 compat 模式，保留旧行为。
3. **OPENCLAW_NO_RESPAWN=1**: systemd 管理环境必须设置，避免 OpenClaw 自带 respawn 与 systemd Restart 冲突（本次踩坑后已加入 service 文件）。
4. **memorySearch 默认 openai**: 无 OpenAI key 时语义搜索不可用，已按决策禁用（文件检索不受影响）。

## 六、后续建议

1. **启用 `/fast auto`**: 轻量任务（巡检、状态查询）用 deepseek 快模型，预计省 token 20-30%
2. **给 cron 加条件触发**: 磁盘告警等改为"变化才唤醒"，减少空跑
3. **跟进 7.2 候选**: 7.2 将带来远程编码会话（cloud worker 上跑 Control UI 会话），对多机协作有价值，等 stable 再评估
4. **网络层风险处置**: OpenClaw 自身安全已加固，但 frps 弱口令 / sing-box 开放代理 / rpcbind 暴露仍在（巡检报告第十一章），建议择机处理
